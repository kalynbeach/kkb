Audio Runtime Architecture

The proposal pivots from app-owned audio orchestration to reusable runtime modules with framework-agnostic controllers. React becomes a lifecycle adapter, UI stays presentation-only, and the demo app becomes a consumer.

04

Contracts to define before refactoring

Contract Decision needed Why it matters Status
Command model How load/play/pause/seek/source switch/destroy serialize or cancel. Prevents interleaved async calls from corrupting transport state. define first
Disposal model Whether destroy is async, idempotent, and legal during pending commands. Resource leaks and double-dispose bugs are likely without this. define first
Error model Typed errors for unsupported source, decode, autoplay, permission, CORS, WebGPU loss. Lets sessions surface recoverable vs fatal states without guessing. define first
Diagnostics Expose source, fallback reason, renderer backend, capability decisions, analysis support. Keeps internals hidden while preserving debuggability. runtime-owned
Resource ownership AudioContext, media elements, worklets, streams, GPU devices, animation frames. Clarifies who creates, reuses, and tears down browser resources. define first
Import safety No browser globals at module import time. Keeps Next/server imports safe and package entrypoints usable. hard rule
Analysis tap Sample rate, clocks, channels, buffers, latency, unsupported-source behavior. Prevents playback visualization from becoming hidden coupling. define first
