## Anti-Patterns Verdict

**Does this look AI-generated? No.** This passes the product-register slop test.

**LLM assessment (A):** No side-stripe borders, gradient text, glassmorphism, hero-metric templates, eyebrow kickers, numbered scaffolding, or decorative grid backgrounds. Radii stay 0–4px, borders carry hierarchy per the Flat Product Rule, audio blue is genuinely scoped, and the TX-02/Geist split is executed consistently. Specimen copy is domain-specific rather than filler. The one drift toward a "generated" tell is template-uniform, thin focused pages — uniform emptiness reads as generated just as uniform density does.

**Deterministic scan (B):** Static CLI scan of `apps/web/app/ui` + `apps/web/components/ui-catalog`: **clean (exit 0)**. Runtime detector injected into the live page found **8 hits**, most attributable to `@kkb/ui` package CSS outside the scanned dirs:

- `nested-cards` ×4 — button group, framed chart specimen, and both `audio-panel`-inside-`audio-shell` specimens. The first two are false positives (segmented control; deliberate specimen frame). The audio pair is intentional device chrome.
- `gpt-thin-border-wide-shadow` ×2 — both `audio-shell` containers. This is the DESIGN.md "Audio Shell" shadow token working as documented: a sanctioned instrument-chrome exception, not a defect.
- `all-caps-body` ×1 — "CLICK WAVEFORM OR USE ARROW KEYS" hint (10px tracked mono). Matches the `audio-label` type role; borderline by rule threshold, intentional by system.
- `layout-transition` ×1 — a `transition: height` somewhere in the live page. Real finding: height transitions animate layout. Worth locating and replacing with a transform/clip approach (P3).

**Where the two assessments diverge:** the detector's audio-surface hits are all design-system-sanctioned exceptions; meanwhile the review caught the one genuinely broken visual (the 0-height chart bars, below) that no static rule flags. Page sanity from B: 0 console errors/warnings, 0 failed network requests, no horizontal overflow at 1440px or 390px.

## Overall Impression

The catalog's plumbing is better than its documentation. URL-as-state, error isolation, scoped color discipline, and consistent focus treatment are instrument-grade — and then the flagship destination (a focused component page) gives you two small boxes in an empty viewport with no import path, no intent, and no title. The single biggest opportunity: make the focused page carry the information a builder actually comes for, starting with a copyable import line.

## What's Working

1. **URL-as-state architecture** (`catalog-workbench.tsx`): `?item=` drives everything, invalid ids self-heal via `router.replace`, and search/rail/compact-nav converge on one `selectItem`. Refresh, share, and back-button all just work.
2. **Color scoping discipline is real, not aspirational.** Audio blue appears only inside audio chrome and labeled swatches; the neutral product surface never borrows it. The Audio category header even documents the rule in the UI.
3. **`DemoBoundary` with `resetKey`** (`catalog-surface-shared.tsx`): per-specimen error isolation with honest fallback copy — most commercial catalogs don't do this.

## Priority Issues

1. **[P1] Broken chart specimen on the default Preview wall.** `DataPreview` (`preview-wall.tsx` ~line 331) sets percentage heights on bars inside a flex column with no definite height — all five bars render at 0px (verified in-browser). The landing view ships a visibly empty "chart." **Fix:** give the bar column a fixed height like the working audio bars in `design-system-surface.tsx` (`h-20` parent, direct children). **Command:** `$impeccable polish`.
2. **[P1] Focused component pages carry zero documentation.** `focusedIntent`, `sourceInstruction`, and `relatedItems` (`catalog-data.ts` 344–393) are exported but unused; the import path — the most-copied string in any catalog — appears nowhere on the page. **Fix:** a compact `SurfaceHeader` variant on focused pages with click-to-copy source path, one-line intent, related items; or delete the dead exports if truly unwanted. **Command:** `$impeccable polish` (or `$impeccable shape` if rethinking the page).
3. **[P1] Rail is invisible to keyboard/AT users and loses the selection.** Desktop `CatalogRail` never scrolls the active item into view (compact nav does — port it); eight buttons announce as bare "All"; group labels are plain `<p>`, so ~60 buttons read as one undifferentiated region with no skip link past them. **Fix:** `scrollIntoView` on selection change, `aria-label="All Input components"` per group, group semantics, and consider `<a href="?item=...">` for rail items (also unlocks cmd-click). **Command:** `$impeccable harden` or `$impeccable audit`.
4. **[P2] Desktop composition collapses on focused pages.** Two-column grid with 2–3 stages leaves ~75% of a 1440px viewport empty (Audio Waveform is one ~500px card). The brief promises boldness through density and rhythm; these pages are neither. **Fix:** a deliberate max-width container, or enrich flagship specimens (states row, keyboard behavior) to earn the canvas. **Command:** `$impeccable layout`.
5. **[P2] The workshop IA exists in data but not on screen.** `railGroups` ("Core bench", "Instrument bays", "Interaction support"), `itemLane`, `laneLabel` are defined and never rendered; the rail is a generic alphabetized category list. **Fix:** render the bench groups as rail super-sections, or remove the dead vocabulary so code and design agree. **Command:** `$impeccable polish` (render) or `$impeccable distill` (remove).

## Persona Red Flags

**Alex (power user):** cannot cmd-click rail items into a new tab (buttons, not links); the most common task — copy an import — requires opening the search dialog and reading an 11px meta line, or opening `catalog-data.ts`; no next/prev between components.

**Sam (keyboard/screen-reader):** eight identical "All" announcements; rail categories are unlabeled `<p>` text, not group semantics; no skip link past ~60 rail buttons. Positives: consistent `focus-visible:ring-[3px]`, proper sr-only DialogTitle/Description, `role="status"` on search counts.

**Riley (stress tester):** the 0-height chart silently breaks while looking like a design choice; the Preview wall mixes one clickable cell (token strip) among visually identical inert ones; the static command-palette preview accepts typing but filters a 3-item fake list — looks functional, does nothing.

## Minor Observations

- `transition: height` in the live page (detector hit) — animating a layout property; replace with transform/clip or drop it.
- `componentDescription()` generates template prose ("Button is part of the input surface in @kkb/ui") that reads AI-ish in the search meta line.
- Document `<title>` never changes per item; tab history is unnavigable.
- `catalog-icons.tsx`: Audio → `Gauge`, Input → `MousePointer2` are loose metaphors; Waveform/Activity fit Audio better.
- `SpecimenStage` titles (12px muted mono) sit at nearly the same weight as body meta — stage hierarchy one notch too quiet.
- Card specimen titles use Title Case while every other stage uses sentence case.
- Suspense fallback in `page.tsx` is a centered bordered box; a workbench-shell skeleton would meet the product bar.

## Questions to Consider

1. If the focused page showed nothing but the specimen plus one copyable import line, would anyone ever need the category surfaces — and if not, what are they for?
2. The bench/bay/lane vocabulary was designed and never rendered. Is the workshop metaphor a real organizing principle or decoration that rightly got cut — and why does the dead code disagree with whichever answer you pick?
3. What would the Preview wall look like if it were honest about interactivity — every cell either a working demo or a labeled link, nothing in between?
