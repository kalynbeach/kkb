## Design Context

### Users
- Primary audience today: internal dev/design collaborators using `/ui` as a working verification and showcase surface for `@kkb/ui`.
- Secondary audience later: external users evaluating the component system and its quality.
- Core jobs to be done: verify primitives and compositions, browse the available catalog, understand what each component is for, and build confidence that the system is coherent and reusable.

### Brand Personality
- Utilitarian, polished, trustworthy.
- The interface should feel engineering-first but not crude: calm, rigorous, and well-made.
- It should avoid feeling generic, templated, or enterprise-admin bland.

### Aesthetic Direction
- Clean, structured, quiet UI with premium restraint rather than visual spectacle.
- Prioritize clear hierarchy, legible labeling, and disciplined spacing over decorative trends.
- Anti-references: generic shadcn demo pages, boilerplate AI-generated component galleries, and corporate admin dashboards.

### Design Principles
1. Make verification feel intentional — even internal tooling should communicate care and product quality.
2. Lead with usefulness first, then layer in presentation quality; never sacrifice clarity for style.
3. Differentiate through composition, hierarchy, and rhythm instead of trendy effects.
4. Keep the catalog scannable: users should quickly understand section purpose, item coverage, and what to inspect next.
5. Build credibility for eventual external viewers now, so the route can evolve from internal utility to public showcase without a redesign from scratch.
