01 — The Problem

From visual oscillators to audible tone sessions

source: plan lines 5–19, 49–69
Before — current experience
  1. User can open /audio for media playback or /oscilloscope for visual oscillator/mic experiments.
  2. Oscilloscope oscillators produce deterministic sample buffers for display, not audible Web Audio output.
  3. The Worklet PCM path exists as a facade, but browser host wiring is intentionally stubbed and opt-in.
  4. No safe UI exists for carrier Hz, beat Hz, fade envelope, headphone guidance, or stop-on-discomfort copy.
After — desired experience
  1. User opens /binaural-beats and sees a focused experimental audio session surface.
  2. User taps Play; the app creates/resumes AudioContext in direct response to the gesture.
  3. Two sine oscillators route to separate stereo channels through gains, merger, and master fade.
  4. User can adjust carrier, beat, volume, and fade within conservative bounds; Stop remains visible.

03 — State Variables

Minimal app state, graph refs outside React render

  • config drives controls and engine updates.
  • status disables conflicting actions and labels UI.
  • error exposes unsupported/resume failures.
  • engineRef avoids recreating audio graph on render.

Engine-private graph state

type Graph = {
  context: AudioContext;
  leftOscillator: OscillatorNode;
  rightOscillator: OscillatorNode;
  leftGain: GainNode;
  rightGain: GainNode;
  merger: ChannelMergerNode;
  masterGain: GainNode;
};

let graph: Graph | null = null;
  • Graph is created lazily from Play.
  • Oscillators stop/disconnect on Stop or Destroy.
  • Master gain owns fade in/out and safety volume.
04 — Modified Functions

New functions and nearby patterns to follow

createBinauralBeatEngine

apps/web/lib/binaural-beats/create-binaural-beat-engine.ts
export const createBinauralBeatEngine = (
  options: CreateBinauralBeatEngineOptions = {},
): BinauralBeatEngine => {
  let graph: BinauralBeatGraph | null = null;

  const play = async (config: BinauralBeatConfig) => {
    const context = graph?.context ?? createContext(options);
    await context.resume();
    graph = graph ?? createGraph(context);
    const safeConfig = sanitizeBinauralBeatConfig(config);
    applyConfig(graph, safeConfig);
    fadeTo(graph.masterGain.gain, safeConfig.volume, safeConfig.fadeSeconds, context.currentTime);
  };

  const stop = async () => {
    if (!graph) return;
    await fadeTo(graph.masterGain.gain, 0, DEFAULT_BINAURAL_BEAT_CONFIG.fadeSeconds, graph.context.currentTime);
    stopAndDisconnect(graph);
    graph = null;
  };

  return { play, update, stop, destroy };
};

New app-local engine. It owns browser audio nodes but exposes a tiny lifecycle API to React.

sanitizeBinauralBeatConfig

apps/web/lib/binaural-beats/binaural-beat-config.ts
export const DEFAULT_BINAURAL_BEAT_CONFIG = {
  carrierFrequencyHz: 400,
  beatFrequencyHz: 10,
  volume: 0.15,
  fadeSeconds: 1,
} satisfies BinauralBeatConfig;

export const sanitizeBinauralBeatConfig = (input: BinauralBeatConfig) => ({
  carrierFrequencyHz: clampFinite(input.carrierFrequencyHz, 100, 900, 400),
  beatFrequencyHz: clampFinite(input.beatFrequencyHz, 1, 30, 10),
  volume: clampFinite(input.volume, 0, 0.35, 0.15),
  fadeSeconds: clampFinite(input.fadeSeconds, 0.1, 3, 1),
});

Pure helper first. This is the easiest place to test safe bounds and invalid numeric input.

BinauralBeatsClient

apps/web/components/binaural-beats/binaural-beats-client.tsx
export function BinauralBeatsClient() {
  const [config, setConfig] = useState(DEFAULT_BINAURAL_BEAT_CONFIG);
  const [status, setStatus] = useState<PlaybackStatus>("idle");
  const engineRef = useRef<BinauralBeatEngine | null>(null);

  const onPlay = async () => {
    setStatus("starting");
    engineRef.current ??= createBinauralBeatEngine();
    await engineRef.current.play(config);
    setStatus("playing");
  };

  useEffect(() => () => engineRef.current?.destroy(), []);
}

Follows existing client-owned lifecycle style from PlayerClient, but remains independent from media playback.

06 — Edge Cases

Boundaries, mistakes, and browser failures

ScenarioExpected behaviorWhy it matters
User clicks Play twice quicklySecond click is ignored or disabled while status === "starting".Prevents duplicate oscillator graphs.
Browser blocks/resume rejectsSet status="error", show retryable message, keep controls visible.Autoplay policy varies by browser/device.
Carrier below 100 or above 900 HzClamp to range before UI and engine use.Matches conservative psychoacoustic bounds from plan.
Beat below 1 or above 30 HzClamp to range and avoid exposing unsupported deltas.Above ~30 Hz is less likely perceived as binaural beating.
Volume too high or NaNClamp to safe cap or default low volume.Audio should never surprise the user.
Stop during fade-inCancel scheduled gain values, fade toward zero, stop/disconnect, and clear graph refs.Avoids clicks, stuck sound, and replaying stopped one-shot oscillators.
Component unmounts while playingCall destroy() in cleanup; no rejected promises leak to UI.Route changes must silence audio.
Headphones not used or mono output enabledUI warns binaural mode may not work; v1 accepts this constrained headphone-only risk. Add stereo check / mono fallback before broader release.Output routing is outside reliable browser control.
OfflineAudioContext missing in testsUse pure helper tests and injected/stubbed graph constructors.Bun/browser API availability may vary.

09 — Implementation Notes

Guardrails that keep v1 small and safe

Backward compatibility

No existing routes, media playback APIs, worklet stubs, or oscilloscope providers need modification. The feature is additive and isolated under a new route.

Critical warning

Do not market this as treatment, therapy, clinical entrainment, sleep cure, anxiety relief, or brainwave control. Keep all copy factual and non-medical.

Accepted v1 risk

Research favors monaural/isochronic support plus stereo check and mono fallback. V1 is intentionally binaural-only; require headphone guidance and add fallback before broader release.
