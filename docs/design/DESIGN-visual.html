What this system should feel like

Sharp enough to feel technical, precise enough to trust, direct enough that the work stays in the foreground.

shadcn-compatible clarity

Controls, demos, docs, and visualizations keep semantic token names aligned with globals.css and @kkb/ui.

One coherent workshop

Experiments can have local character, but the shared token and component vocabulary prevents routes from becoming separate products.

Hard-edged by default

Most controls and panels use 1-4px radii. Full rounding is reserved for badges, avatars, sliders, and switches.

Initial intent retained from the backup

The backup remains a reference for original direction. This visual keeps its useful decisions while tightening language around the new spec.

Neutral-first foundation

The original spec established white, near-black, quiet gray borders, semantic foreground pairs, and compact shadcn-derived controls.

Audio as scoped exception

The original design already separated the tactile audio layer: cool blue accents, recessed panels, scanlines, and hardware-like controls.

Typography restored

TX-02 carries headings, labels, code, telemetry, and hardware-style UI. Geist handles prose; Mekzantine carries the primary serif voice, with EB Garamond and Departure Mono kept selective.

Operating rules

These are the durable constraints that should guide future agents and feature work.

The Scope Rarity Rule

Scope Blue belongs to signal, selection, and audio instrument state. If it appears as general decoration, it is wrong.

The Semantic Token Rule

Use shadcn/ui token names in docs and components. Descriptive names are prose, not replacements for semantic token names.

The Flat-Until-Earned Rule

A resting product surface should not look lifted. Shadows must communicate overlay, active state, or instrument depth.

Do

  • Build from @kkb/ui tokens and components first.
  • Keep body text at WCAG AA contrast.
  • Use 1-4px radii for most controls and panels.
  • Use borders and tonal layering before shadows.

Don't

  • Make KKB feel vibe-coded, corporate, or like generic glossy SaaS.
  • Use heavy gradients, rounded soft cards, pillowy inputs, or decorative color drift.
  • Use display fonts in labels, buttons, data, or controls.
